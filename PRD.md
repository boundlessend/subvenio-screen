# ScreenFilter - work breakdown

How the app was built, wave by wave. Architecture decisions and their reasoning
live in [PLAN.md](PLAN.md); this file holds the sequence of work and the check
that closed each wave.

Principle: every wave ends in a state you can launch and verify by hand. A wave
is not closed until its check has passed.

**Status: all seven waves are closed.** What each check actually produced is
recorded below.

---

## Wave 0: skeleton - done

**Goal:** an empty app that lives in the menu bar and builds with one command.

**Work:**

1. Xcode project, macOS App, Swift. Generated by XcodeGen from `project.yml`,
   which stays in git while the `.xcodeproj` does not.
2. `LSUIElement = true`. No Dock icon, menu bar only.
3. `NSStatusItem` with a minimal menu.
4. `.gitignore` for Swift/Xcode.
5. Minimum target: **macOS 13.0**. Rationale: `SMAppService` for launch at login
   without a helper bundle (13.0+), a mature ScreenCaptureKit (12.3+), a usable
   SwiftUI settings scene.

**Check passed:** the app launches, the icon is in the menu bar, nothing in the
Dock (`background only = true`), Quit works.

**Learned:** `@main` on an `NSApplicationDelegate` does not wire the delegate up
without a NIB - the app launches with an empty menu bar. The entry point is
`main.swift` setting the delegate explicitly.

## Wave 1: MVP - done

**Goal:** one effect, one hotkey, work continues through it.

**Work:**

1. **Overlay window.** `NSWindow`, `.borderless`, `isOpaque = false`,
   `backgroundColor = .clear`, `hasShadow = false`, `ignoresMouseEvents = true`,
   level `CGWindowLevelForKey(.screenSaverWindow)`, collection behaviour
   `.canJoinAllSpaces`, `.stationary`, `.fullScreenAuxiliary`, `.ignoresCycle`,
   and `sharingType = .none` from the start.
2. **Metal layer.** `CAMetalLayer` as the backing layer, `.bgra8Unorm`,
   `framebufferOnly = true`, premultiplied alpha out of the shader.
3. **First shader**, hardcoded: scanlines plus vignette, level 2.
4. **Global hotkey** through Carbon, not `NSEvent.addGlobalMonitorForEvents`,
   which would demand Accessibility.
5. **Menu bar:** an on/off item.
6. **Persistence:** on/off state in `UserDefaults`.

**Check passed:** the overlay sits at level 1000 across the full display; a real
`CGEvent` click lands in the app underneath; the hotkey toggles it; state
survives a restart.

**Note for later:** `sharingType = .none` also hides the overlay from
`screencapture`, so the effect cannot be verified with a screenshot. Verify by
window geometry, by offscreen rendering of the shader, or by eye.

## Wave 2: plugin engine - done

**Goal:** shaders stop being part of the binary.

**Work:**

1. **Plugin format:** a folder with `shader.metal` and a JSON manifest holding
   the name, the render level and the parameters with ranges and defaults.
2. **Location:** `~/Library/Application Support/ScreenFilter/Shaders/`. Bundled
   presets are installed folder by folder, existing folders untouched.
3. **Loader:** scan, parse, validate. A broken manifest or a shader that does
   not compile shows up in the UI with its error text rather than being skipped.
4. **Runtime compilation:** `device.makeLibrary(source:options:)`.
5. **Uniforms:** time, resolution, display scale, manifest parameter values.
6. **Three presets** on top of the engine: scanlines, film grain, VHS.

**Check passed:** a new plugin dropped into the folder appears in the menu with
no rebuild; a broken manifest and a broken shader each produce a readable error
and the app keeps running.

**Deviation from the plan:** no on-disk pipeline cache. Compilation measured at
10-11 ms per shader after warmup, so an in-memory cache is enough. Marked with a
`ponytail:` comment where the upgrade would go.

---

## Wave 3: level 1, gamma LUT - done

**Goal:** a second rendering backend and an abstraction over levels.

**Work:**

1. **Abstraction:** the manifest declares the level, the engine picks the
   backend, exactly one stays active.
2. **Applying the LUT:** `CGSetDisplayTransferByTable` on the selected display,
   tables generated from the preset (tint, gamma, inversion, clipping).
3. **Restoring gamma.** Critical: `CGDisplayRestoreColorSyncSettings()` on
   normal termination and from a signal handler. Without it a crash leaves the
   screen tinted with no explanation.
4. **Reapplying:** gamma is reset by the system on wake, colour profile change
   and display reconfiguration, so we subscribe to those.

**Check passed:** read back with `CGGetDisplayTransferByTable`, sepia matches
the computed values exactly; the table is linear again after normal quit, after
SIGTERM, and after `kill -9` (WindowServer restores it there).

---

## Wave 4: level 3, screen capture - done

**Goal:** honest pixel transforms, including black and white.

**Work:**

1. **Onboarding:** an explanation screen of our own before the system dialog,
   shown lazily on first use of a level 3 preset.
2. **Capture:** `SCStream` with `SCContentFilter` excluding the app's own
   windows. Together with `sharingType = .none` from wave 1 this closes the
   feedback loop from both sides.
3. **Frame path:** `CMSampleBuffer` → `CVPixelBuffer` → `CVMetalTextureCache` →
   `MTLTexture` → shader → `CAMetalLayer`, with no CPU copy.
4. **Stream settings:** `minimumFrameInterval` from the display refresh rate,
   `showsCursor = false` by default, buffer scale as the performance lever.
5. **First level 3 shader:** black and white.
6. **Refusal handling:** if the permission is missing or revoked, the app says
   so and keeps working on levels 1 and 2.

**Check passed:** capture runs at about 5% CPU with the system recording
indicator lit; the shader was verified by pushing a real screenshot through the
pipeline; refusing the permission leaves levels 1 and 2 working.

**Learned:** a `nonisolated async` function runs off the main thread, so
`NSWindow` creation moved into `MainActor.run` and `NSScreen` values are read on
the main thread. Signing moved from ad-hoc to a real Apple Development
certificate, because TCC binds the grant to team id plus bundle id and an ad-hoc
signature loses it on every rebuild.

---

## Wave 5: settings window - done

**Goal:** control without editing files by hand.

**Work:**

1. State moved out of `AppDelegate` into an observable `EffectController`.
2. SwiftUI settings window with the preset list and live parameter sliders.
3. Hotkey assignment through `KeyboardShortcuts`, conflict checking included.
4. Display selection, threaded through all three backends.
5. A cursor option for level 3 with an honest warning about the lag.

**Check passed:** a slider moves the running effect and persists; the hotkey
still toggles after moving to the library; the cursor toggle appears only for
level 3 presets.

**Deliberately not done:** independent presets on several displays at once. That
needs one controller per display and cannot be verified on a single-monitor
machine. The target display is selectable.

---

## Wave 6: window-scoped mode - done

**Goal:** the effect only in the area of a chosen window.

**Work:**

1. Window selection from a live list.
2. Position and size tracking. The fork from PLAN.md resolved in favour of
   polling `CGWindowList` over Accessibility: one lookup by window id measures
   at 0.08 ms, which is 0.5% of a core at 60 Hz.
3. Reaction to moving, resizing, minimising and closing the target window.
4. `Uniforms` gained `sourceOrigin` and `sourceSize`, so a level 3 shader
   samples the matching slice of the display frame.

**Check passed:** the overlay rect matches the target window exactly, follows
moves and resizes, and minimising the window drops the effect while the app
keeps running.

**By nature:** level 1 stays full-screen, since a gamma table applies to the
whole display. The settings window says so.

---

## Wave 7: launch at login - done

**Goal:** the app comes up with the system.

**Work:**

1. `SMAppService.mainApp.register()` behind a settings toggle.
2. Restoring the last effect on autostart, which came for free from wave 1.

**Check passed:** registered, relaunched, the toggle was still on; unregistered,
it went off. The toggle reads its state from the system rather than from
`UserDefaults`, so a failed registration cannot show as enabled.

---

## After the waves

Fixed since: flicker at level 3, caused by capture frames being released before
they were drawn and by the view drawing a level 3 shader with no source texture.

Still open, from the deferred list in PLAN.md: versioning and release cadence,
testing on Intel, displays with different scale and refresh rate, the real
project name.

Checks that need a human and have not been run: behaviour in full-screen apps
and Mission Control, gamma after a real sleep cycle, a second monitor, a reboot
for launch at login.
