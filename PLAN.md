# screen-filter - вопросы для планирования

Идея: лёгкое macOS-приложение, накладывающее визуальные фильтры/эффекты
(старый ТВ, ЧБ, VHS и т.п.) поверх всего происходящего на экране,
с включением/выключением по горячей клавише.

Ниже - вопросы для планирования. Отвеченные фиксируются как решения,
неотвеченные остаются открытыми до следующего раунда.

## Принятые решения

1. **Назначение и охват.** Сейчас - приватный репозиторий, для личного
   использования. Публикация в Mac App Store не планируется. Позже
   репозиторий станет открытым (open source) для всех. Вопросы
   версионирования и релизного ритма отложены - будут записаны отдельно
   позже, к этому вернёмся перед открытием репозитория.
2. **Технический подход.** Не выбираем один способ навсегда - оба
   бэкенда нужны как режимы на выбор:
   - Core Image + прозрачное overlay-окно (лёгкий режим, без разрешения
     Screen Recording) - для эффектов, которым не нужен захват пикселей
     построчно.
   - Metal + ScreenCaptureKit (как у RetroVisor) - для эффектов, которым
     нужен полноценный захват экрана.
   Архитектура должна закладывать абстракцию над бэкендом рендеринга
   эффекта, чтобы конкретный фильтр мог заявить, какой бэкенд ему нужен.
3. **Область применения эффекта.** Трёхуровневая схема:
   - один глобальный хоткей - эффект на все подключённые мониторы сразу;
   - дополнительные хоткеи, настраиваемые на отдельный монитор
     (multi-monitor: можно выбрать конкретный дисплей);
   - отдельный режим в настройках - эффект только в области под
     конкретным окном (как у RetroVisor).
4. **Каталог эффектов и формат шейдеров.** Не фиксированный список
   пресетов - с первого дня движок с поддержкой произвольных шейдеров
   как плагинов. Готовые фильтры (ЧБ, старый ТВ и т.д.) - лишь первые
   пресеты поверх этого движка, а не хардкод. Формат авторинга шейдера -
   оба сразу: Metal (MSL) и Core Image (CIKernel), плагин заявляет,
   каким из двух он написан.
5. **UI и настройка.** Меню-бар иконка для быстрого переключения
   пресетов + отдельное полноценное окно настроек для хоткеев, шейдеров
   и per-monitor/per-window правил.
6. **Права доступа.** Разрешение Screen Recording (нужно для
   Metal+ScreenCaptureKit режима) - приемлемо, но перед системным
   диалогом Privacy & Security нужен собственный экран онбординга,
   объясняющий, зачем это нужно, а не голый системный запрос без
   контекста.
7. **Нефункциональные требования на старте.** В первой версии сразу:
   автозапуск при старте macOS и запоминание последнего включённого
   эффекта между перезапусками.

## Открытые вопросы

## 6. Дифференциация от аналогов

- Чем это должно отличаться от уже существующих RetroMac / RetroVisor /
  Black Light 3 - или это осознанный "свой велосипед" ради контроля
  и обучения?

## 7. Курсор и системные элементы

- Эффект должен захватывать курсор мыши и системные элементы (меню-бар,
  Dock), или обходить их?

## 8. Распространение

- Нужна ли нотаризация Apple для распространения за пределами
  локальной машины (актуально, когда репозиторий станет открытым)?

## 9. Стек и ограничения

- Swift + SwiftUI/AppKit - вариант по умолчанию для лёгкого нативного
  macOS-приложения, есть возражения?
- Нужны ли сторонние зависимости, или ограничиваемся системными
  фреймворками (Core Image, Metal, Carbon/EventKit для хоткеев)?
- Целевая версия macOS и архитектура (Apple Silicon only или + Intel)?
- Ограничение по нагрузке: какой процент CPU/GPU считается приемлемым
  в простое и во время активного эффекта?
